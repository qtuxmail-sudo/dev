# Next.js 14 portfolio/brand hub with dark motorsport aesthetic

A single-page portfolio site built from scratch with Next.js 14 App Router, Tailwind CSS, and Framer Motion. The site follows the landonorris.com pattern: full-screen hero with parallax, sticky header with scroll-aware blur, animated stats, product carousel, esports section, countdown timer, and newsletter footer. Everything renders client-side via `"use client"` directives on every component; the root page acts as a thin server component stitching them together.

**Watch for:** Hydration mismatch from the countdown timer computing time on the server vs. client (confirmed). Newsletter form has no submission handler — it's purely cosmetic but users can interact with it (confirmed). Every section loads images from Unsplash without blur placeholders, which will produce visible layout shift on slower connections (confirmed).

## High-level view

The architecture is a single `page.tsx` that imports eight client components rendered sequentially. There's no routing, no data fetching, no API layer — this is a static marketing page that happens to use React for scroll animations. The server/client boundary is effectively at the page level since every component opts into client rendering.

The countdown timer in `RaceCalendar` uses a hardcoded target date (`2025-07-01T14:00:00Z`) with a `setInterval` ticking every second. This creates a hydration risk: the server render computes a time value, and the client picks up a different value milliseconds later. The target date is also already in the past, so the timer permanently shows zeros.

Image handling relies entirely on Unsplash URLs configured through `next.config.mjs` remote patterns. No `placeholder="blur"` or `blurDataURL` is used anywhere, so every image will flash in on load. The `priority` flag is correctly set on the hero image but absent elsewhere.

The newsletter form in the footer accepts email input but the button has no `onClick` and the elements aren't wrapped in a `<form>`. Clicking "Subscribe" does nothing — no feedback, no submission, no error.

## Countdown timer and hydration gap

`RaceCalendar` initializes state with `useState(getTimeRemaining(TARGET_DATE))`. During SSR, this computes a value based on server time. When the client hydrates (potentially seconds later), React reconciles against the server-rendered HTML and finds a different number, producing a visible flicker.

```tsx
const [timeLeft, setTimeLeft] = useState(getTimeRemaining(TARGET_DATE));
```

The fix: initialize with `null` or a static placeholder, then populate on first client effect. Alternatively, add `suppressHydrationWarning` on the timer elements.

The target date itself (`2025-07-01T14:00:00Z`) is hardcoded and already past. The `if (diff <= 0)` guard clamps to zeros, but the interval keeps ticking every second indefinitely for the lifetime of the page — wasted CPU cycles on a single-page site where this component never unmounts.

## Image loading strategy

Six components use `next/image` with Unsplash URLs. Only the hero sets `priority={true}`. The shop carousel is particularly affected: six 400px-wide images in a horizontal scroll container, all at `aspect-[3/4]`, all rendering as blank charcoal rectangles until loaded. On mobile connections this produces several seconds of empty UI as the user scrolls.

Adding `placeholder="blur"` with generated blur hashes (or a simple `bg-charcoal` class on the parent, which some containers already have) would eliminate the visual jank.

## Mobile menu scroll leak

The header's mobile overlay (`motion.div` with `fixed inset-0`) covers the viewport visually, but the body behind it remains scrollable. On iOS Safari in particular, touch scrolling will pass through the overlay and move background content. The fix: toggle `document.body.style.overflow = "hidden"` in an effect keyed to `menuOpen`.

## SVG icon duplication

The Header renders Instagram, Twitter, and YouTube SVG paths in both the desktop nav and the mobile overlay — six inline SVGs with identical path data. The Footer repeats all three again. That's nine copies of the same three icons. Extracting shared icon components would eliminate ~2-3KB of repeated markup and centralize social link management.

## StatsBar: reveal animation vs. counting animation

The spec describes "animated numbers" but the implementation uses a simple opacity+translateY reveal via Framer Motion variants. The numbers appear at their final value instantly — there's no counting animation from 0 to N. If counting is desired, a `useMotionValue` + `animate` or `requestAnimationFrame` counter is needed.
